# Развёртывание лёгкой версии

## Что требуется

Linux-сервер с Docker Engine и Compose v2, 2 vCPU, 2 ГБ RAM, SSD от 10 ГБ, домен и открытые порты 80/443. База H2 хранится в постоянном Docker-томе `schitay_app_data`; отдельный сервер PostgreSQL не запускается.

## Запуск

1. Скопируйте `.env.example` в `.env` и заполните домен, администратора, оператора и SMTP.
2. Убедитесь, что адрес `MAIL_FROM` разрешён вашим почтовым провайдером.
3. Выполните `docker compose up --build -d`.
4. Проверьте `docker compose ps` и `https://ваш-домен/actuator/health`.

`ADMIN_EMAIL` и `ADMIN_PASSWORD` создают администратора только при отсутствии такого пользователя. Пароль существующего аккаунта меняется через восстановление доступа.

## Почта

Приложение использует обычный SMTP, поэтому подходит любой совместимый сервис. Настройки: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_AUTH`, `SMTP_STARTTLS`, `MAIL_FROM`. Сообщения сначала фиксируются в `mail_outbox`, затем отправляются фоновым заданием; при ошибке выполняется до пяти попыток.

Для локальной проверки выполните `docker compose -f compose.demo.yml up --build -d`. Mailpit принимает письма внутри Docker без отправки в интернет; интерфейс доступен по адресу `http://localhost:8025`. Mailpit предназначен только для разработки.

Для реальной доставки настройте у домена SPF, DKIM и DMARC. Для собственного сервера дополнительно нужен PTR/rDNS и контроль репутации IP. Без этих записей письма могут попадать в спам независимо от кода приложения.

## Резервные копии

`scripts/backup.sh` кратко останавливает приложение, архивирует постоянный том и снова запускает приложение. Это необходимо для согласованной копии файловой базы. Восстановление: `scripts/restore.sh backups/имя.tar.gz --confirm-replace-database`. Перед восстановлением сделайте свежую копию и храните архивы вне сервера.

## Ограничения

Файловая H2 рассчитана на один экземпляр приложения и умеренную нагрузку. Не запускайте несколько экземпляров с одним файлом базы. Для масштабирования и высокой доступности следует вернуться к серверной СУБД. Сессии находятся в памяти и после перезапуска требуют повторного входа; марафоны, задания и ответы сохраняются.

# Развёртывание и эксплуатация

## Production: один сервер

Рекомендуемый старт: Linux, 2 vCPU / 4 ГБ RAM, SSD 20+ ГБ, Docker Engine + Compose v2, публичный домен, открытые 80/tcp и 443/tcp/udp. Постоянное время сервера синхронизируется NTP. PostgreSQL и Java не публикуют порты наружу. Единственная внешняя точка — Caddy.

1. Перенесите репозиторий на сервер. Укажите DNS A/AAAA домена на сервер; неправильный AAAA удалите или исправьте.
2. `cp .env.example .env`, `chmod 600 .env`. Заполните домен без схемы, email ACME, случайный пароль БД, уникальный пароль администратора (10+ символов), телефон, ключ SMS.RU, юридическое имя оператора и контакт для обращений.
3. `scripts/deploy.sh`. Скрипт проверяет заполнение, собирает образ с тестами, запускает Compose и ждёт healthcheck.
4. Откройте `https://ваш-домен`, войдите администратором. Проверьте `/actuator/health`, назначьте педагогов, создайте первый марафон.
5. На своём тестовом телефоне проверьте восстановление пароля и полный сценарий задания.

`ADMIN_PHONE`/`ADMIN_PASSWORD` используются только для создания отсутствующего аккаунта. Изменение переменной не меняет пароль существующей записи. Для смены пароля используется восстановление по SMS. Секреты не коммитятся. Демо запрещено в production.

Профиль prod требует PostgreSQL, SMS_MODE=smsru, SMS_API_KEY, OPERATOR_NAME и OPERATOR_CONTACT. Проверка оператора нужна для отображения конкретных документов пользователю; перед работой с реальными детьми оператор утверждает свой текст документов и сроки хранения. Приложение не выдаёт юридическую гарантию соответствия законодательству.

## SMS

Используется официальный HTTP API SMS.RU: POST `https://sms.ru/sms/send`, form-urlencoded `api_id`, `to`, `msg`, `json=1`. Успех проверяется и для ответа целиком, и для конкретного номера. Timeout 10 секунд; до пяти попыток с увеличением интервала. Ключ не записывается в аудит.

Событие сохраняется в одной транзакции с действием. Отправка раз в 10 секунд. Перед отправкой уведомления проверяются согласие и активность аккаунта. Код восстановления пароля отправляется по запросу пользователя. `SENT` означает, что провайдер принял сообщение.

LOCAL не отправляет SMS. Для проверки OTP в изолированном Docker-демо:

```sh
docker compose -f compose.demo.yml exec db psql -U schitay -d schitay \
  -c "select body from sms_outbox where service=true order by created_at desc limit 1;"
```

Не используйте эту команду для чужих настоящих кодов. Административный API показывает только метаданные SMS, без тела и OTP. Доставка at-least-once: при неоднозначном сетевом исходе возможен дубль сообщения. Это не удваивает результат или баллы.

## Резервное копирование

`scripts/backup.sh` создаёт закрытый custom-format dump в `backups/`. Настройте серверный cron, например ежедневно 03:15 по времени сервера:

```cron
15 3 * * * cd /srv/schitay && ./scripts/backup.sh >> /var/log/schitay-backup.log 2>&1
```

Храните зашифрованную копию вне сервера; права 0600, ограниченный доступ. Стартовая политика — 14 ежедневных копий; удаление/ротацию согласуйте с оператором. Не храните бэкапы в Git. Регулярно проверяйте восстановление в отдельную БД.

Восстановление (заменяет данные):

```sh
scripts/backup.sh
scripts/restore.sh backups/schitay-YYYYMMDDTHHMMSSZ.dump --confirm-replace-database
```

Приложение останавливается на восстановление. При ошибке restore скрипт не запускает его автоматически; проверьте причину и восстановите предыдущую копию.

## Обновление и откат

1. Сделайте backup и сохраните SHA текущего коммита/образа.
2. Получите новый релиз, запустите тесты, `scripts/deploy.sh`.
3. Миграции Flyway применяются автоматически. Уже применённые миграции не редактировать.
4. Откат образа допустим только при совместимой схеме. Иначе остановите приложение, восстановите backup и предыдущий образ.

Сессии хранятся в памяти Java и после перезапуска требуют входа заново. Таймеры и ответы находятся в PostgreSQL и сохраняются. Поставка рассчитана на один экземпляр приложения; для горизонтального масштабирования нужны общие сессии и координация фоновых обработчиков.

## Мониторинг и диагностика

- `docker compose ps`, `docker compose logs --tail=100 app`, `/actuator/health`.
- Администратор → журнал и SMS-очередь. FAILED требует проверки баланса/ключа провайдера; не редактируйте результаты SQL-запросами.
- Точные времена и записи попыток — UTC; границы дней вычисляются в timezone марафона (по умолчанию Europe/Moscow).
- Фоновая финализация каждые 15 секунд; чтение/запись задания также финализирует истёкшую попытку. Ответ после серверного дедлайна не принимается даже в этом 15-секундном интервале.
- При потере сети клиент показывает отсутствие сохранения и повторяет запрос. Сервер может проверить только реально доставленные до дедлайна ответы.
- Не публикуйте Compose demo и не открывайте PostgreSQL наружу.

## Внешние настройки, которые появятся с инфраструктурой

Домен и DNS; сервер; резервное хранилище; настоящий SMS.RU аккаунт/баланс/ключ; реквизиты оператора; удалённый Git. Их отсутствие не мешает локальной работе и сборке комплекта, но исключает проверку публичного TLS и реальной SMS-доставки.

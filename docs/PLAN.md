# План реализации «Считай»

Статус на 05.11.2026: этапы 1–7 выполнены. Итоги автоматических, браузерных и Docker-проверок — [QA.md](QA.md); фактический публичный деплой отложен до появления инфраструктуры.

Приоритет: пожелания заказчика от 05.11.2026 выше исходного ТЗ. Полный веб-продукт, Java backend, самостоятельные решения, коммиты этапов. Инфраструктура отсутствует: поставка готового Docker Compose, без заявления о публичном деплое.

## 1. Проектирование (первый коммит)
- Сохранить исходное ТЗ, сформировать сценарии и HTTP-контракты.
- Определить модель прав, состояний, времени, импорта и генерации.
- Выбрать визуальное направление через Product Design.

## 2. Основа и безопасность
- Maven, Java 21, Spring Boot, PostgreSQL/Flyway; H2 только локально и в быстрых тестах.
- Сессионная аутентификация, BCrypt, CSRF, безопасные cookies, ограничения входа и OTP.
- Отдельные согласия, подтверждение телефона, восстановление пароля, роли PARENT/TEACHER/ADMIN.
- Профили детей, управление пользователями, журнал действий.

## 3. Марафоны, материалы и назначения
- Независимые марафоны, несколько педагогов, расписание с IANA timezone.
- CSV UTF-8: category,topic,level,expression,answer; ограничения размера/строк, транзакционный импорт.
- Генерация из нескольких библиотек, фильтры категории/уровня/темы, выбор без повторов, ошибка при нехватке.
- Ручные задания, копирование, индивидуальные назначения, массовое назначение нескольким детям.

## 4. Выполнение и результаты
- Серверный старт, дедлайн min(start+30min, next midnight), автосохранение с версией.
- Атомарная отправка, автоматическое завершение, отдельные ошибки/пропуски/пропущенные дни.
- Повторное открытие с новой попыткой, подтверждённой причиной, сохранением предыдущей истории.
- Рейтинг по сумме, равные места, протокол очной встречи без изменения баллов.
- CSV отчёты по марафону и ребёнку, защита от формул CSV.

## 5. Веб-интерфейс
- Русский адаптивный интерфейс для родителя, педагога, администратора.
- Экран выполнения: крупные поля, таймер, прогресс, предупреждения, подтверждение отправки.
- Все кнопки и формы подключены к backend; пустые/ошибочные/загрузочные состояния.
- Доступность: семантика, клавиатура, подписи, фокус, контраст, мобильная ширина.

## 6. Операционная поставка
- Транзакционная SMS outbox, SMS.RU и локальный transport, повторные попытки и дедупликация.
- Docker multi-stage, PostgreSQL, Caddy/HTTPS, healthcheck, тома, секреты через окружение.
- CI, backup/restore, инструкция установки, примеры файлов и демонстрационный набор.

## 7. Проверки в несколько итераций
1. Unit/интеграционные: авторизация, владение, генерация, таймер, рейтинг, CSV, OTP.
2. Сквозные HTTP-сценарии: регистрация → ребёнок → марафон → назначение → решение → отчёт.
3. Визуальная проверка desktop/mobile и исправление обнаруженного.
4. Финальный clean verify, проверка production-конфига, git status и отчёт с честными ограничениями.

## Принятые решения
- Один правильный ответ = один балл, независимо от сложности.
- Категории BABY/SCHOOL; уровни BASIC/MEDIUM/HARD; возраст описывает библиотеку, категория задаёт участие.
- CSV выбран вместо XLSX: редактируется Excel/LibreOffice, формат прозрачен и тестируем.
- Рейтинг виден авторизованным участникам марафона при публикации организатором. Полные ФИО; отдельное согласие на публикацию.
- Доступ ребёнка только через родителя. Педагоги не проходят задания за детей.
- Техническое повторное открытие доступно на 24 часа, новая попытка получает полные 30 минут, сохраняется предыдущий результат до её начала, после начала результат пересчитывается по новой попытке.
- При отмене марафона запись ответов блокируется; результаты сохраняются.
- Результаты становятся финальными после завершения всех открытых попыток, включая технические переоткрытия.
- Уведомления в полночь предусмотрены ТЗ; отправка только при отдельном согласии.
- SMS delivery at-least-once: дедупликация события в БД, при неоднозначном сетевом исходе возможна повторная доставка провайдером.

# Техническое задание  
## Платформа для марафона по ментальной арифметике

### 1. Назначение системы

Платформа предназначена для проведения образовательных марафонов по ментальной арифметике. В рамках каждого марафона дети в течение 6 дней получают индивидуальные задания, решают их в ограниченное время, а система автоматически проверяет ответы, рассчитывает результаты и ведёт общий рейтинг.

Система должна поддерживать проведение нескольких марафонов одновременно, с независимыми участниками, педагогами, расписаниями, заданиями и рейтингами.

### 2. Роли пользователей

| Роль | Возможности |
|---|---|
| Родитель | Регистрируется, создаёт профили детей, выполняет задания вместе с ребёнком, видит подробные результаты |
| Педагог | Создаёт марафоны и задания, назначает их детям, просматривает результаты и ошибки |
| Администратор | Управляет пользователями, марафонами, педагогами, настройками и журналом действий |

Ребёнок не получает отдельный логин. Все действия с заданиями выполняются в кабинете родителя, который выбирает нужный профиль ребёнка и открывает доступное задание.

Согласие на обработку персональных данных должен давать родитель как законный представитель ребёнка. Согласие должно быть конкретным, информированным и подтверждаемым.[1][2]

# 3. Структура марафона и задания

## 3.1. Марафоны

Система должна поддерживать несколько независимых марафонов.

Для каждого марафона задаются:

- название;
- описание;
- дата начала;
- дата окончания;
- количество дней — по умолчанию 6;
- часовой пояс — Europe/Moscow;
- педагог или группа педагогов;
- статус: черновик, запланирован, идёт, завершён, отменён;
- настройки публикации результатов и рейтинга.

Каждый марафон имеет собственный список участников, задания, результаты и рейтинг. Данные одного марафона не должны смешиваться с данными другого.

## 3.2. Дни марафона

Один марафон состоит из шести последовательных дней:

- День 1;
- День 2;
- День 3;
- День 4;
- День 5;
- День 6.

Для каждого дня и каждого ребёнка создаётся отдельное задание.

| Событие | Время | Действие системы |
|---|---:|---|
| Открытие задания | 00:00 МСК | Задание текущего дня становится доступным |
| Закрытие предыдущего задания | 00:00 МСК | Невыполненное задание предыдущего дня закрывается |
| Первый запуск задания | По нажатию «Начать задание» | Запускается индивидуальный таймер на 30 минут |
| Автоматическая отправка | Через 30 минут | Ответы сохраняются и проверяются |
| Закрытие задания | 23:59:59 МСК | Невыполненное задание получает статус «Не выполнено» |

Пропуск дня не блокирует участие в последующих днях.

## 3.3. Статусы задания

| Статус | Описание |
|---|---|
| Черновик | Задание создано, но не назначено |
| Запланировано | Задание назначено, но ещё не открыто |
| Доступно | Задание открыто, ребёнок может начать |
| В работе | Таймер запущен, ребёнок выполняет задание |
| Отправлено | Работа отправлена на проверку |
| Проверено | Автоматическая проверка завершена |
| Время истекло | 30 минут закончились, работа завершена автоматически |
| Не выполнено | Ребёнок не начал работу до закрытия задания |
| Закрыто | Задание недоступно для прохождения |
| Повторно открыто | Задание открыто повторно после технического сбоя |

## 3.4. Состав задания

Каждое индивидуальное задание содержит:

- название марафона;

- инструкцию для ребёнка;
- список примеров;
- поле для ответа к каждому примеру;
- счётчик заполненных ответов;
- таймер обратного отсчёта;

## 3.5. Индивидуальные задания

Педагог назначает каждому ребёнку собственный набор примеров. Дети одной категории — «дошкольник» или «школьник» — могут получать разные задания.

Для каждого ребёнка педагог задаёт:

- день марафона;
- количество примеров;
- текст каждого примера;

Задания могут создаваться вручную, копироваться из другого дня или профиля, а также загружаться массово из файла XLSX или CSV.

## 3.6. Формат примера

| Поле | Тип | Описание |
|---|---|---|
| Номер примера | Число | Порядковый номер |
| Текст примера | Текст | Например: 25 + 14 - 7 |
| Правильный ответ | Число | Эталон для автоматической проверки |
| Балл за правильный ответ | Число | По умолчанию 1 |
| Порядок показа | Число | Очерёдность примеров |

| Примечание педагога | Текст | Необязательное поле |

На первом этапе поддерживаются числовые ответы: целые положительные и отрицательные числа. Дробные, текстовые, аудио- и графические ответы не требуются, если не будут отдельно согласованы.

## 3.7. Открытие и выполнение

До 00:00 соответствующего дня ребёнок в кабинете родителя видит карточку:

> «Задание откроется [дата] в 00:00».

После 00:00 появляется кнопка «Начать задание». Таймер запускается только после нажатия кнопки.

При первом открытии система:

- фиксирует серверные дату и время старта;
- переводит задание в статус «В работе»;
- запускает таймер на 30 минут;
- сохраняет промежуточные ответы;
- показывает оставшееся время;
- предупреждает за 5 минут и за 1 минуту;
- не позволяет перезапустить таймер при обновлении страницы или повторном входе.

Отсчёт времени должен рассчитываться на сервере. Если ребёнок войдёт с другого устройства, он должен увидеть продолжение того же таймера, а не получить новые 30 минут.

## 3.8. Отправка и проверка

Ребёнок может завершить работу вручную кнопкой «Завершить и отправить» либо система автоматически отправит ответы по истечении 30 минут.

Перед ручной отправкой выводится предупреждение:

> «После отправки изменить ответы будет нельзя. Завершить работу?»

После отправки система:

- фиксирует дату и время завершения;
- запрещает редактирование ответов;
- сравнивает каждый ответ с эталонным;
- начисляет 1 балл за правильный ответ;
- отдельно фиксирует неправильные ответы;
- отдельно фиксирует пропущенные ответы;
- рассчитывает итог за день;
- обновляет рейтинг;
- сразу показывает ребёнку количество ошибок.

### Правила подсчёта

| Тип ответа | Баллы | Учёт в результате |
|---|---:|---|
| Правильный ответ | 1 | Учитывается как правильный |
| Неправильный ответ | 0 | Учитывается как ошибка |
| Пустой ответ | 0 | Учитывается как пропуск |
| Не начатое задание | 0 | Учитывается как пропуск всего дня |

Формула:

\[
\text{Баллы за день} = \text{Количество правильных ответов}
\]

Итог марафона:

\[
\text{Итоговые баллы} = \sum_{i=1}^{6} \text{Баллы за день } i
\]

## 3.9. Результат после проверки

Сразу после автоматической проверки ребёнок и родитель видят:

- статус: «Работа выполнена»;
- количество набранных баллов;
- количество правильных ответов;
- количество ошибок;
- количество пропусков;
- подробные ответы по каждому примеру;
- место в рейтинге, если рейтинг опубликован.

Родитель должен видеть подробные ответы, а не только итоговый балл. Для каждого примера отображаются:

- текст примера;
- правильный ответ;
- ответ ребёнка;
- результат: верно, ошибка или пропуск;
- начисленный балл.

# 6. Рейтинг

## 6.1. Общий рейтинг

В каждом марафоне формируется отдельный рейтинг.

В рейтинге отображаются все участники, включая детей, которые пропустили один или несколько дней.

Для каждого участника показываются:

- место;
- полные фамилия и имя;
- категория: дошкольник или школьник;
- баллы за День 1;
- баллы за День 2;
- баллы за День 3;
- баллы за День 4;
- баллы за День 5;
- баллы за День 6;
- итоговое количество баллов;
- количество выполненных дней;
- количество пропущенных дней.

## 6.2. Сортировка

Основная сортировка — по убыванию итогового количества баллов.

При равном количестве итоговых баллов система не определяет победителя автоматически. Таким участникам присваивается одинаковый промежуточный статус:

> «Равный результат — требуется очная встреча».

После очной встречи администратор или педагог должен иметь возможность зафиксировать итоговое распределение мест по решению организаторов. Это единственный случай, когда итоговое место может быть скорректировано вручную; сами баллы, ошибки и ответы при этом остаются неизменными.

## 6.3. Обновление рейтинга

Рейтинг пересчитывается автоматически после:

- проверки каждой отправленной работы;
- автоматического закрытия невыполненного задания;
- повторного прохождения задания после технического сбоя;
- изменения статуса марафона.

Рейтинг должен обновляться без ручного пересчёта со стороны педагога.

- доступ педагога только к участникам назначенных ему марафонов;
- серверную проверку таймера;
- запрет повторной отправки работы;
- запрет изменения ответов после отправки;
- журналирование входов, изменений заданий, повторных открытий и результатов;
- резервное копирование базы данных;
- защиту от подмены времени на устройстве пользователя.

# 10. Критерии приёмки

Система считается принятой, если:

1. Родитель может зарегистрироваться и добавить профиль ребёнка.
2. Родитель выбирает категорию ребёнка: дошкольник или школьник.
3. Система поддерживает несколько марафонов одновременно.
4. Педагог создаёт и назначает индивидуальные задания каждому ребёнку.
5. Задания открываются автоматически в 00:00 МСК.
6. Предыдущее задание закрывается при открытии следующего.
[04.11.2026 23:45] Папа: 7. Таймер на 30 минут запускается при первом открытии задания.
8. Таймер не сбрасывается при обновлении страницы или входе с другого устройства.
9. Ответы автоматически проверяются после отправки.
10. За каждый правильный пример начисляется 1 балл.
11. Ошибки и пропуски учитываются раздельно.
12. Ребёнок и родитель сразу видят количество ошибок.
13. Родитель видит подробные ответы по каждому примеру.
14. Педагог видит количество ошибок и пропусков по каждой работе.
15. Педагог не может вручную изменять результат.
16. При техническом сбое задание может быть повторно открыто с фиксацией причины.
17. Пропустившие день дети отображаются в рейтинге с 0 баллов.
18. Рейтинг обновляется автоматически.
19. В рейтинге отображаются полные фамилия и имя участников.
20. При равных баллах система помечает участников для очной встречи.
21. Родитель получает SMS-уведомления о ключевых событиях.
22. Ребёнок не имеет отдельного логина и работает только из кабинета родителя.

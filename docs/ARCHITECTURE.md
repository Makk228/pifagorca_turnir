# Архитектура и принятые ограничения

Модульный монолит: Spring MVC JSON API + статический SPA с same-origin запросами. Один артефакт JAR. Библиотеки frontend не требуются в runtime. PostgreSQL — источник истины; H2 поддерживается для локального старта и быстрой серии тестов.

## Модули

- `Auth`, `RateLimiter`, `SecurityConfig`: сессии, BCrypt, CSRF, OTP, согласия, ограничения.
- `Marathons`: профили детей, доступы, расписание, участники, педагоги.
- `Libraries`: строгий CSV и фильтруемая случайная выборка SecureRandom.
- `Assignments`: назначения, копирование, серверное время, попытки, версии, проверка, переоткрытие.
- `Rankings`: суммы, пропущенные дни, равные места, очный протокол и CSV.
- `Sms`, `Jobs`: транзакционная outbox, доставка и обработка дедлайнов.
- `Api`: HTTP-граница; все бизнес-проверки находятся также в сервисах.

## Модель

`users → children → enrollments → marathons`. `marathon_teachers` определяет область доступа. `libraries → library_examples` хранит импорт. `assignments → examples` содержит неизменяемую после старта копию задания. `attempts → answers` хранит все прохождения; assignment.current_attempt определяет учитываемое. `reopen_events`, `audit`, `consents` сохраняют историю действий. `sms_outbox` отделяет расчёт результата от внешнего провайдера.

## Конкурентность

Изменения задания сериализуются `SELECT ... FOR UPDATE` по assignment. Генерация и копирование блокируют marathon, предотвращая гонку замены/создания. Optimistic version на попытке выявляет работу с нескольких устройств. Повторный start возвращает тот же таймер; submit завершённой попытки возвращает тот же результат. Уникальные ключи защищают назначение на ребёнка/день и SMS-события.

Начало и дедлайн — серверные Instant. Обычный дедлайн `min(start + 30 минут, начало следующего дня)`; техническое переоткрытие разрешает старт 24 часа и полные 30 минут после старта. Старые ответы могут быть восстановлены, старый attempt сохраняется. Открытие новой попытки/завершение/переоткрытие аннулирует решения очной встречи для марафона.

Неначатый закрытый день вычисляется как MISSED, даёт 0 и учитывается отдельно от пустых полей в начатой работе. Шесть дней — default; поддерживается 1–31. Даты начала фиксируются при создании, чтобы поздняя правка расписания не сдвинула уже выданные задания.

## Изоляция данных

Родитель — только свои дети и их задания. В опубликованном рейтинге видит участников своего марафона с учётом согласия на ФИО. Педагог — только назначенные марафоны и свои библиотеки, администратор — все. Правильные ответы родителю не выдаются до финализации. После повторного старта эталоны снова скрыты, но ранее увиденный разбор нельзя «забыть»: переоткрытие предполагает подтверждённый технический инцидент, а не механизм повторного соревнования.

## Эксплуатационная область

Один экземпляр приложения, PostgreSQL, Caddy. Нет оплаты, нативного приложения, детских логинов, дробных/графических ответов. Импорт и экспорт CSV, как разрешено ТЗ; XLSX не реализуется. Отправка SMS проверяет приём провайдером, delivery callbacks не подключены. Полный список фактически проведённых и не проведённых проверок — в QA.md.

Технические источники: [Spring Boot requirements](https://docs.spring.io/spring-boot/3.5/system-requirements.html), [SMS.RU API](https://sms.ru/docs/api/api_group_sms/send).

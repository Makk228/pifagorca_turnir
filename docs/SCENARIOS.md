# Пользовательские сценарии и критерии

## Родитель
1. Регистрация: ФИО, телефон, пароль ≥ 10 символов, раздельные согласия. Обязательны условия, персональные данные и участие; SMS и публикация рейтинга отдельные. Подтверждение телефона кодом, срок 10 минут, максимум 5 ошибок. Отказ от SMS не блокирует приложение; сервисный код запрашивается явно.
2. Вход по телефону и паролю. Ошибки не раскрывают существование пользователя. Восстановление через одноразовый SMS-код, прежние сессии перестают работать.
3. Добавление нескольких детей: ФИО, год рождения, категория. Родитель видит только своих детей.
4. Вступление по коду марафона после подтверждения телефона. Назначенный педагог видит участников только своего марафона.
5. Выбор ребёнка и дня: будущие задания заблокированы, пропущенные дни не мешают следующим.
6. Первый старт фиксируется сервером. Повторный старт возвращает ту же попытку и дедлайн. Ответы сохраняются автоматически, после обновления восстанавливаются. Конфликт двух устройств не затирает данные молча.
7. Ручная отправка требует подтверждения. Дедлайн завершает сохранённую работу даже без браузера. Правильные ответы не выдаются в API до завершения.
8. Результат: баллы, ошибки, пропуски, полный разбор; история по марафонам и опубликованный рейтинг.
9. Настройки согласий: родитель может отозвать SMS и публикацию рейтинга; новые уведомления не отправляются, ФИО скрывается из родительского рейтинга.

## Педагог
1. Администратор назначает роль. Педагог создаёт марафон с датами, числом дней (по умолчанию 6), timezone, инструкцией и настройкой рейтинга.
2. Приглашает участников кодом; администратор назначает дополнительных педагогов.
3. Импортирует несколько CSV-библиотек с названием, проверяет число примеров. Некорректная строка отклоняет весь файл.
4. Выбирает детей, день, библиотеки, категории, уровень, тему, число примеров. Каждый ребёнок получает случайную выборку без повторов внутри задания. Недостаток примеров отклоняет запрос целиком.
5. Создаёт вручную либо копирует задание в другой день/другому ребёнку. Начатые задания защищены от замены.
6. Смотрит результаты и подробные ответы, скачивает общий/подробный CSV.
7. Подтверждает технический сбой, вводит причину. Система хранит предыдущую попытку и запись аудита; новый результат возможен только после прохождения.
8. После завершения марафона фиксирует порядок участников внутри равной по баллам группы и основание очной встречи. При изменении результатов протокол утрачивает актуальность.

## Администратор
1. Первичная учётная запись из переменных окружения (без production-пароля по умолчанию).
2. Управляет ролями/активностью пользователей; назначает педагогов марафону; просматривает все марафоны.
3. Просматривает аудит и очередь SMS. Не редактирует баллы.
4. Делает backup и проверяет restore по runbook.

## Негативные сценарии
- Подмена childId/assignmentId/marathonId → 403/404 без утечки данных.
- Доступ педагога к чужому марафону/библиотеке → 403.
- Ответ после дедлайна → завершение по ранее сохранённым данным; поздний ответ не засчитывается.
- Повторная отправка → тот же результат без двойных баллов/SMS.
- Произвольный текст вместо целого числа → 400; пустое поле = пропуск, 0 = полноценный ответ.
- Ошибка SMS не откатывает результат; outbox сохраняется и повторяет доставку.
- CSV с HTML → хранится как текст, отображается безопасно; CSV с формулой обезвреживается при экспорте.

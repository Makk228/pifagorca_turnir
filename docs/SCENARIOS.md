# Пользовательские сценарии и критерии

## Родитель
1. При регистрации родитель вводит 10 цифр номера после фиксированного +7 и пароль от 6 символов. Обязательны условия, согласия на обработку данных и участие. Публикация ФИО в рейтинге добровольна.
2. Вход по телефону и паролю. Ошибки не раскрывают существование пользователя. Восстановление через одноразовый SMS-код, прежние сессии перестают работать.
3. При добавлении ребёнка родитель указывает ФИО, полную дату рождения, пол и категорию. Для существующей карточки в разделе «Мои дети» можно указать или изменить дату рождения. Аватар зависит от пола. Для старого профиля с инициалом нажмите «Указать пол». Родитель видит только своих детей. В этом же разделе можно удалить карточку после подтверждения. Она и её задания исчезают из кабинета родителя, а результаты остаются у педагога.
4. Родитель выбирает ребёнка и вступает по коду марафона. Назначенный педагог видит участников своего марафона.
5. Выбор ребёнка и дня: будущие задания заблокированы, пропущенные дни не мешают следующим.
6. Первый старт фиксируется сервером. Повторный старт возвращает ту же попытку и дедлайн. Ответы сохраняются автоматически, после обновления восстанавливаются. Конфликт двух устройств не затирает данные молча.
7. Ручная отправка требует подтверждения. Дедлайн завершает сохранённую работу даже без браузера. Правильные ответы не выдаются в API до завершения.
8. Результат: баллы, ошибки, пропуски, полный разбор; история по марафонам и опубликованный рейтинг.
9. В разделе «Мой профиль» родитель может отозвать согласие на публикацию ФИО. ФИО скрывается из родительского рейтинга.

## Педагог
0. При создании марафона задаёт отдельное время выполнения и количество примеров для дошкольников и школьников. Может сразу прикрепить Excel-силлабус или заменить его позднее в «Настройках». Количество берётся из файла. В генераторе строки NF/F5/F10+/F10/FF идут в порядке силлабуса — от простого к сложному; умножение и деление с единицей исключаются.
1. Администратор назначает роль. Педагог создаёт марафон с датой начала, числом дней (по умолчанию 6), часовым поясом, инструкцией и настройкой рейтинга. В настройках марафона можно изменить дату начала. Расписание сдвигается, а сроки уже начатых попыток сохраняются.
2. Приглашает участников кодом; администратор может одним действием назначить марафону нескольких педагогов. Каждый назначенный педагог видит всех участников, их задания, ответы и результаты в пределах этого марафона.
3. Загружает CSV-файлы в разделе «Библиотеки» и при загрузке указывает категорию соревнования для каждого файла. Проверяет число примеров. Некорректная строка отклоняет весь файл. Ненужный файл можно удалить после подтверждения. Его примеры сохраняются в уже созданных заданиях.
4. Во вкладке «Участники» видит имя, школьную группу и возраст ребёнка в полных годах на текущую дату. Выбирает и сохраняет категорию соревнования для каждого участника. В окне «Индивидуальные задания» может выбрать группу соревнования и возраст, затем уточнить список галочками. Для каждой категории выбранных участников педагог обязан выбрать ровно один файл библиотеки с той же категорией. Файл другой категории и два файла одной категории отклоняются до создания заданий. Каждый ребёнок получает случайную выборку без повторов внутри задания. Недостаток примеров отклоняет запрос целиком.
5. Во вкладке «Задания» открывает работу конкретного ребёнка и видит все примеры с правильными ответами. Пока ребёнок не начал выполнение, педагог может нажать «Изменить задание», исправить, добавить или удалить строки и изменить инструкцию. После начала попытки редактирование блокируется.
5. Создаёт задание вручную либо копирует его в другой день или другому ребёнку. При ручном вводе форма предлагает открытые и будущие дни, в которых у выбранного ребёнка ещё нет начатого задания.
6. Открывает «Рейтинг» марафона и видит отдельные таблицы школьников и дошкольников. В общем CSV место указано внутри школьной группы, а категория заданий приводится справочно. Подробные ответы можно скачать отдельно.
7. Подтверждает технический сбой, вводит причину. Система хранит предыдущую попытку и запись аудита; новый результат возможен только после прохождения.
8. После завершения марафона фиксирует порядок школьников или дошкольников с равными баллами и основание очной встречи. При изменении результатов протокол утрачивает актуальность.

## Администратор
1. Первичная учётная запись из переменных окружения (без production-пароля по умолчанию).
2. Управляет ролями/активностью пользователей; назначает педагогов марафону; просматривает все марафоны. Во вкладке «Марафоны» может удалить марафон после предупреждения. Вместе с марафоном необратимо удаляются задания, попытки, ответы, результаты, силлабус и его состав; аккаунты пользователей и карточки детей сохраняются.
3. Просматривает аудит и очередь SMS. Не редактирует баллы.
4. Делает backup и проверяет restore по runbook.

## Негативные сценарии
- Подмена childId/assignmentId/marathonId → 403/404 без утечки данных.
- Доступ педагога к чужому марафону/библиотеке → 403.
- Ответ после дедлайна → завершение по ранее сохранённым данным; поздний ответ не засчитывается.
- Повторная отправка → тот же результат без двойных баллов/SMS.
- Произвольный текст вместо целого числа → 400; пустое поле = пропуск, 0 = полноценный ответ.
- Ошибка SMS не откатывает результат; outbox сохраняется и повторяет доставку.
- CSV с HTML → хранится как текст, отображается безопасно; CSV с формулой обезвреживается при экспорте.
